# Responsive audit — existing Betanor platform

**Scope:** existing Next.js routes and shared UI only. No second mobile app is introduced. The production site was inspected read-only on 7 October 2026; route-family roots explicitly described as measured below were checked at a 390px CSS viewport, and the route inventory was also reviewed from the App Router source. A screenshot review covered a desktop workspace and mobile Noren/dashboard. The audit does not submit forms, change records, or test account credentials.

## Viewport and evidence record

The user-supplied target widths are 320, 360, 375, 390, 414, 430, 768, 820, 1024, 1280, and 1440px+. The production route sweep measured the route roots listed above at 390px; a desktop screenshot was captured at the browser's default ~1168px width, and the Noren page was reviewed at 390px. That sweep found:

- `/workspace`: 458px document width at 390px, caused by the long personalized greeting.
- `/workspace/projects`: 418px document width at 390px, caused by a card's intrinsic minimum width/status/content.
- `/workspace/tasks`: 883px at 768px and 1,177px at 1,024px, caused by a four-column task toolbar and table layout starting before the workspace content area was wide enough. The layout now keeps the header/toolbar stacked until extra-wide screens and delays the multi-column list to `xl`.
- `/portal/support` with the current staff preview account redirected to `/workspace`; the measured overflow was the same dashboard greeting, not proof of a customer-side support view.
- Other sampled route roots had no page-level horizontal overflow at 390px. Table/calendar elements may intentionally scroll inside their own bounded region.

This pass fixes the two measured overflow sources, improves Noren mobile navigation, and adds shared mobile/safe-area rules. It does **not** claim physical-device verification or a full screenshot of every route at all 11 widths. Dynamic IDs, role-specific visibility, video/camera permissions, real attachment upload, print/PDF output, and installed iOS/Android behavior still require the device/account checks in the release checklist below.

## Shared responsive standards now applied

- `viewport-fit=cover`; public, staff, and customer headers account for top safe area.
- Main chat/install controls account for right/bottom safe areas and the iOS home indicator.
- Mobile form text is 16px or larger, minimizing iOS auto-zoom; shared dialogs become internally scrollable bottom sheets on phones.
- Workspace navigation stays a drawer on phones and collapses on wide layouts; it is not rendered as a shrunken desktop sidebar.
- Project cards and the personalized greeting allow intrinsic content to wrap. Workspace customer chat is hidden in staff workspace, where Noren already provides staff communication.
- Tables and calendars should retain local horizontal scrolling where a card/list conversion is not practical; do not let these widen the document.
- Noren mobile flow becomes a single focused conversation at a time; tablet/desktop retains split-pane inbox.

## Release QA still required

Before declaring the complete matrix signed off, run actual browser/installed-device checks at 320, 360, 375, 390, 414, 430, 768, 820, 1024, 1280, and 1440px+ for route families that include large tables/forms. Test Android Chrome/install and iOS Safari/Add to Home Screen; verify login/logout, role-specific nav, local table scrolling, Noren composer with keyboard open, authorized file/camera upload, calls, support ticket details, tender checklist/detail, letter editing/preview/download, finance/export screens, and settings in permitted roles. Those actions were deliberately not simulated against production data during this read-only audit.
