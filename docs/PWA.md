# Betanor PWA

Betanor remains one Next.js application for the public site, staff workspace, and customer portal. The PWA is a delivery mode for that same authenticated platform; installation does not create a separate account, database, role, or permission boundary.

## Application identity

- Name: **Betanor Digital Business Platform**; short name: **Betanor**.
- Start URL and scope: `/`, so an installed launch enters the normal site and existing Supabase session/role routing remains authoritative.
- Display: `standalone`; orientation: `any`.
- Brand colors: navy `#0b264f`, background `#f4f7fb`, with the official Betanor B mark and gold accent.
- Manifest: generated by `src/app/manifest.ts` at `/manifest.webmanifest`.
- Browser/app icons use resized copies of the official Betanor logo: `/betanor-icon-192.png`, `/betanor-icon-512.png`, and the 32px `/favicon.ico`. The maskable manifest entry uses the 512px logo image. Apple Home Screen and Next.js app-icon conventions also use the official logo (`/apple-icon.png`, `/icon.png`). The original `/betanor-logo-v1.png` remains unchanged.
- Root metadata enables Apple web-app mode and uses `viewport-fit=cover` for safe-area layout.

## Service worker and cache policy

`public/sw.js` is registered from the root client runtime at `/sw.js` with scope `/`. The response is served with JavaScript content type and `no-cache, no-store, must-revalidate` headers so browsers check for updates.

| Resource | Strategy | Reason |
| --- | --- | --- |
| Offline page and 192px Betanor logo | Precached during install | Generic, non-sensitive recovery UI |
| Hashed `/_next/static/` build files | Cache-first, then network and cache successful same-origin responses | Content-addressed scripts/styles/fonts are safe to reuse |
| Page navigations | Network-only; show the generic offline page on a network failure | Avoid storing personalized SSR, customer, or staff HTML |
| API, RSC/data, Supabase, signed URLs, messages, and other private content | Not cached by the service worker | Preserve authorization, freshness, and signed-URL expiry |

The application deliberately does not attempt a full offline database, task, message, payroll, or document sync. Online-only actions must reach their normal server/RLS authorization to succeed. The service worker does not queue requests or report a business action as successful offline.

## Install and update behavior

- Chromium browsers can show an install button after `beforeinstallprompt`; the browser owns the actual install confirmation.
- iPhone/iPad Safari gets the manual instruction **Share → Add to Home Screen**. iOS does not expose the Chromium install event.
- The suggestion can be dismissed; the choice is remembered for 30 days. Installed mode hides it.
- A waiting worker produces “A new version of Betanor is available.” The user must choose **Update now**; the notice asks users to save unfinished changes first. There is no background `skipWaiting` or automatic reload.
- On foreground return the registration checks for a newer worker. Old Betanor static-cache versions are removed only when the replacement activates.

## Offline and security boundaries

Offline navigation renders `public/offline.html`, which contains no user or business records. After reconnecting, the user reloads and the server re-evaluates the current session and permissions. Auth secrets, API responses, RSC payloads, chats, employee/HR data, customer-scoped records, finance, signed files, and notification content are never put in Cache Storage. Supabase Auth, RBAC, customer scoping, and database RLS remain the access controls in browser and installed mode alike.

No web-push subscription or notification credential is created by this PWA foundation. Web Push remains a future channel in the existing notification-preference architecture; enabling it requires an approved VAPID key lifecycle, subscription storage, user preference controls, and server-side event delivery. Existing in-app/email/Telegram delivery is unchanged.

## Responsive and mobile behavior included

- Global safe-area viewport support, safe top bars, and a safe-area-aware customer chat affordance.
- Mobile text inputs use 16px minimum type to avoid Safari auto-zoom.
- Shared dialogs become bottom sheets with internal scrolling on narrow screens; navigation drawers use dynamic viewport height.
- Workspace greeting and project cards allow long content to wrap without widening the page.
- Noren conversation navigation is list-first on mobile; opening a conversation replaces the list with the conversation and a back-to-list control. Desktop retains its two-pane view.
- Install/update notices sit above the chat affordance and use accessible actions.

## Validation checklist

1. Open `/manifest.webmanifest`; check name, scope, display, colors, the two primary icons, and maskable icon response.
2. In Chrome/Edge DevTools → Application, verify `/sw.js` is active and page navigations/APIs are absent from Cache Storage.
3. Install from a Chromium browser and confirm standalone launch reaches Betanor without gaining permissions.
4. On iOS Safari, use Share → Add to Home Screen; launch from the Home Screen and check notch/home-indicator spacing.
5. With the worker active, go offline and open a new route: the generic offline page should appear; reconnect and reload.
6. Publish a new worker revision: confirm it waits, **Update now** activates it, and no update occurs without the user's choice.
7. Run `pnpm build` and `pnpm lint`; inspect PWA manifest and static-resource responses over the deployed HTTPS origin.

## Browser support / known limits

HTTPS is required outside localhost. Install UX and iOS startup/splash screens are browser/OS-managed and vary by device; no proprietary native wrapper or orientation lock is used. The official logo is provided as PNG files at the favicon, Apple Home Screen, and PWA icon sizes. Push, background sync, offline drafts, and offline mutation queues are not enabled.
